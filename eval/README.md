# 评测

两层评测，回答两个不同的问题：

| 层 | 回答 | 状态 |
| --- | --- | --- |
| 确定性基线 `baseline.py` | 计算模型（预警分级、数据质量、复燃报警）在标准场景上是否按期望工作 | 可用 |
| 智能体端到端 `agent/` | Agent 是否调用了正确的工具、委派给正确的 Agent、数值是否有依据、守住红线 | 首个用例可用 |

## 确定性基线

```bash
make eval                                       # 全部场景
uv run --project mcp python eval/baseline.py s6 # 指定场景
```

逐小时推进模拟时钟（不经过大模型），记录每个预警等级的首次到达时间、最高等级、复燃报警时间，和 `expectations.yaml` 对照。明细写入 `var/eval/baseline.json`（含高温点真实温度，便于画“真实温度 vs 预警等级”的图）。

**期望值是开发占位**——阈值和场景参数都还没审定，目前只用于防回归。专家审定阈值后，应同步审定期望。

已发现并修复的问题：s6 中上隅角 CO 漂移 +7 ppm 未被交叉校核识别、误报蓝色预警（`fire-model/quality.py` 的容差由 2.5 倍收紧为 1.5 倍）。

## 智能体端到端

```bash
make dev                                         # 另开终端；记下打印的带 token 地址
make eval-agent ARGS="--url 'http://127.0.0.1:3080/?token=…' \
    --model deepseek-official/deepseek-flash --model rescue-local/qwen35-122b-a10b --repeat 3"
uv run --project mcp python eval/agent/grade.py <会话 id>   # 对任意已有会话离线判定
```

- 用例在 `agent/cases.yaml`：场景 + 模拟时刻 + 对总指挥协调的提问 + 判定规则。运行时把模拟矿井重置为手动时钟并快进到该时刻，评测期间时钟不走（避免 #8 那样指挥与子 Agent 取数相差十几个模拟小时）。
- `agent/run.py` 经 DSH 网页端提问（Playwright 无头浏览器）。DSH 0.2.1-rc.4 的 headless 和 ACP 入口不支持 Agent 预设，只能这样驱动。`--model` 取网页模型下拉里的 `提供方/模型 id`；网页端选模型会改写配置档的默认模型，跑完自动恢复原来的。
- `agent/grade.py` 读 `.dsh-home/sessions` 下的会话日志判定，规则：委派到指定预设、未调用 actions、输出的数值都能在该 Agent 看到的材料（工具结果、工具参数、收到的消息，含技能原文）里找到、点名的服务或工具确实调用过。
- 每个用例重复多次，按“通过次数/运行次数”汇总；明细写 `var/eval/agent/<时间>/results.jsonl`。

数值溯源的局限（启发式，结论要人工看明细）：

- 按报告写的小数位四舍五入匹配；报告写整数而材料里只有能四舍五入到它的小数（如 43.998 → 44）时只作“整数近似”提醒，因为小整数很容易碰巧对上（编造的“8%”就因材料里有 7.519 被归为提醒）。
- Agent 自己计数、求差、换算出的数（人数合计、时间跨度、温差）也判为不通过——按约定这些应来自代码。
- 子 Agent 照抄指挥 Agent 转述的旧数据不会被发现（转述内容算作它看到的材料）。
- 编号、日期时刻、条号节号、列表序号会先剔除；剔除规则漏掉的格式会产生误报。

还没有的：更多用例（升级、封闭方案、人工确认被拒等）、按回合时刻检查“该调用时调用了”、报告质量的人工或模型评分。
