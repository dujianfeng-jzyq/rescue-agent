# 评测

两层评测，回答两个不同的问题：

| 层 | 回答 | 状态 |
| --- | --- | --- |
| 确定性基线 `baseline.py` | 计算模型（预警分级、数据质量、复燃报警）在标准场景上是否按期望工作 | 可用 |
| 智能体端到端（待建） | Agent 是否在正确的时间调用正确的工具、给出正确的结论、守住红线 | 设计中 |

## 确定性基线

```bash
make eval                                       # 全部场景
uv run --project mcp python eval/baseline.py s6 # 指定场景
```

逐小时推进模拟时钟（不经过大模型），记录每个预警等级的首次到达时间、最高等级、复燃报警时间，和 `expectations.yaml` 对照。明细写入 `var/eval/baseline.json`（含高温点真实温度，便于画“真实温度 vs 预警等级”的图）。

**期望值是开发占位**——阈值和场景参数都还没审定，目前只用于防回归。专家审定阈值后，应同步审定期望。

已发现并修复的问题：s6 中上隅角 CO 漂移 +7 ppm 未被交叉校核识别、误报蓝色预警（`fire-model/quality.py` 的容差由 2.5 倍收紧为 1.5 倍）。

## 智能体端到端（计划）

- 用例 = 标准场景 + 时间点 + 问题 + 判定规则，例如“s4 第 40 小时，问是否需要升级 → 必须调用 escalate_emergency 或建议升级；不得下发缺少注惰的封闭方案”。
- 判定优先用可机读的证据：审计日志、指令台账、工具调用序列；只有报告质量才用人工评分或模型评分。
- 每个用例固定随机种子和模拟时刻，结果可复现；同一用例跑多次，统计通过率。
- 运行方式待 DSH 验证清单完成后确定（DSH 网页端 API 或会话回放）。
