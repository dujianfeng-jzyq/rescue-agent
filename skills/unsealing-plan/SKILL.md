# 启封评估与启封审批

> 状态：草稿，待专家审定。条件和步骤在 `references/readiness.yaml`，全部是开发占位值；SKILL.md 正文不写阈值。

## 怎么用

1. 评估启封一律调固定流程 `assess_unsealing(panel)`：按 `references/collect.yaml` 采集证据，运行脚本 `unsealing_plan.py`，生成报告和要点。
2. 回答时把 `brief_markdown` 原样单独成段放进回答，不改写、不另写分析；逐项判定的数值和“满足/不满足”都由脚本给出，不要自己比较。
3. **结论是“具备启封条件”** 且指挥人员要求启封时，调 `approve_unsealing`，参数只给 `record_id`（照抄 `record_ids.unseal`）。这是 C 级对外动作：弹出人工确认（总指挥），guard 执行前再核对记录和红线；被拒绝就如实说明，不换名目再提交。
4. **结论是“不具备”** 时不要提交，照抄不满足的项；条件变化后重新评估。不要建议“先启封再看”。

## 边界

- 启封方案的步骤顺序固定（先检查、断电、撤人，再启封，再观测），由红线 RL-164 强制；不要自己增删步骤。
- 启封后出现复燃征兆时，立即重新研判；研判结果的 `reseal_indicated` 为真就按 `fire-incident-management` 的“启封后复燃”重新封闭，不在本技能里另写一套。
