# 方案合规审核

> 状态：草稿，规则和审核项由通风部门和救护队审定后上线。审核项和对照条文的范围在 `references/review.yaml`，是开发占位。
> 由第一版的 `red-line-rules` 草稿迁移。红线规则只在 `rescue_contract/redlines.py` 实现一次（规则表见下），本技能不重复实现。

## 怎么用

合规审核是固定流程 `draft_sealing_plan`、`draft_firefighting_plan` 的一个阶段，不单独调用：

1. 流程把方案交给 actions 的红线预检（`precheck_plan`，与下发时的强制校验同一套规则）；
2. `scope.py` 按方案的步骤和依据给出要对照的条号和审核项清单，流程从条文索引取原文；
3. 阶段“合规审核”（模型）逐项给出结论（通过 / 不通过 / 需人工决策）、引用的条号（只能从给定条文里选）和一句说明；
4. `review.py` 定结论：红线预检不通过，或任一审核项不通过，结论为不通过，意见退回“方案编写”；轮数用完仍不通过时交回指挥人员。

## “合规审核”阶段怎么判

逐项看方案文本，每个审核项都要给结论：

- **依据**：方案依据和步骤说明里写的条号，与给定条文的内容对得上。对不上才判不通过。
- **现场条件**：缺失的条件（写“缺失”的）已经列在“待补充”或人工确认项里，就是通过；不要因为条件缺失本身判不通过——依赖缺失条件的红线由规则引擎按不放行处理。
- **现场侦察**：密闭位置、顶板支护、供电状态等系统没有数据的条件，方案写明需现场侦察确认的为通过。
- **封闭顺序**：先注惰、先临时密闭后永久密闭由必备步骤保证；看补充说明有没有与之矛盾的内容。
- **职责边界**：方案只提出任务和安全要求；替救护队规定小队编成、行进路线等行动细节的判不通过（第46条）。
- **撤人**：撤人步骤写明按预案立即执行、不等待本方案的为通过。

防灭火方案（`draft_firefighting_plan`，`scope.py` 给出的审核项是依据、现场条件、不进入灾区、通风稳定）不封闭火区、不安排人员进入灾区，没有上面的现场侦察、封闭顺序、撤人三项，改按下面判：

- **不进入灾区**：方案和补充说明里没有安排人员进入灾区作业的步骤、没有替救护队规定行动细节的为通过（第46条）。
- **通风稳定**：均压、堵漏等措施的说明里没有反风、风流短路、停主要通风机的内容的为通过（第98条）。

判“不通过”时，说明写清楚要怎么改，且必须是“方案编写”阶段改得了的（可选步骤、密闭巷道（封闭方案）、补充说明）；
涉及现场条件、人工确认项、必备步骤的问题判“需人工决策”，由确认人在下发时把关。拿不准的判“需人工决策”，不要判不通过。

说明里只写方案和条文里有的数值，不换算、不估算、不计数；只引用给定的条号，不凭记忆引用其他条文。

## 读审核意见

- 结论、不通过的项数由代码给出，照抄；
- 红线预检不通过时，照实转告问题和条号，不要改写规避；
- “需要确认人把关”的事项会在下发时的人工确认弹窗里逐项列出。
