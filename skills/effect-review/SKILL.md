# 处置效果复评

> 状态：草稿，待通风/防灭火专家按本矿制度审定。判据在 `references/effect.yaml`，测点范围在 `references/collect.yaml`，全部是开发占位值。
> 由第一版 fire_model 的 `evaluate_effect_panel` 和 workflow 的 `review_effect` 迁移。

## 怎么用

评估处置效果一律调固定流程 `review_effect(panel, since?)`：

- `since` 是处置开始的矿井时间。指挥人员给了就照填；没给时流程从指令台账取本工作面最近一次已下发的封闭方案或防灭火方案的下发时间，没有方案时取加密监测的开始时间（报告里写明来源）。只有加密监测时没有采取处置：结论写成“未采取处置：趋势恶化 / 上升减缓 / 停止上升 / 观测时间不足”，起算时间叫“观察起点”，照抄，不要说成“处置效果”；台账里也没有就会报错，这时问指挥人员处置是什么时候开始的，不要自己猜。
- 流程按采集清单取处置前一段时间到现在的数据，运行 `effect.py`，生成复评报告。报告事实部分原样放进回答。

## 结论怎么来的（脚本给出，照抄）

- 逐个测点比较处置前、处置后的上升速率：停止上升为“已受控”，明显减缓但仍上升为“需继续处置”，没有明显减缓或处置后新出现标志气体为“恶化”；处置后观测时间不够一个观测周期的为“观测时间不足”。
- 汇总：任一测点恶化为恶化；参与判定的测点全部已受控为已受控；否则需继续处置；观测时间不足的测点不参与。
- 各结论测点数、按类型分组的测点数、已观测时长、下次复评时刻都由脚本算好。不要自己数测点、相减算变化、推算时长。

## 解读

- “恶化”时提醒指挥人员重新研判（`run_fire_assessment`），由升级建议判断是否升级为应急响应；撤人按预案执行，不等待任何结果。
- “观测时间不足”不是“无效”，按报告给出的下次复评时刻再评估。
- O₂ 下降、采空区 CH₄ 波动不说明火情好坏，不作为效果指标。
- 封闭后效果的最终判断（火区是否熄灭、能否启封）由专家决定，本技能不给启封判据。
