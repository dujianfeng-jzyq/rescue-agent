# 第四版设计：通风图地图界面（草案）

状态：**P0 验证完成（2026-11-08），P1 底图与界面打磨、大屏外壳完成（2026-11-09），P2 地图实时叠加完成（2026-11-09），P3 起待实施**。验证记录见 `docs/validation-checklist.md` #25–#30。

## 1. 目标

把 DSH 网页端改成“下层是矿井通风图、上层是半透明悬浮的信息和对话”：

- 下层：某矿的通风立体图（内部演示用），可平移、缩放、倾斜。
- 上层：左侧矿井信息，右侧智能体信息，底部聊天框；都是半透明悬浮，可以单独隐藏，全隐藏时只剩地图。
- 智能体可以根据情况**定位、缩放、标记**地图（“看哪里”由智能体指给操作员），监听器告警时镜头自动飞到出事位置。

不做：在图上编辑巷道、在图上直接下发处置（对外动作仍然只走 guard 和人工确认）。

## 2. 底图是什么（`var/ventnet.dwg` 的分析结果）

DWG（AutoCAD 2018）里有两张图，坐标相隔很远：

| 图 | 内容 | 用途 |
|---|---|---|
| **iso**（主视图） | 《某矿 采一区通风立体示意图》（2023 年 9 月）。**斜轴测画法**：各水平层叠放，巷道画成平行四边形条带，每段标风量（m³/min），有 44 个巷道/设施名称标注，右侧图例，右下角标题栏 | 地图主视图 |
| plan（备选） | 《通风系统示意图》（SKTF06，2022 年 2 月），平面图，引线和标注很密 | 备选视图，图例和图框范围还没量准，暂不输出 |

要点：

- **没有可靠的三维高程**。转换出来的 Z 值是乱的；“立体”来自斜轴测画法本身。所以“倾斜视角”只是正交相机绕 X 轴倾斜，用来拉开层次，不是真三维。真三维要另有标高数据（各水平标高表或测量数据）。
- 巷道是双线（两帮），没有中心线，也没有网络拓扑。图只用来**看**，不参与计算；拓扑和风量仍以矿井接口为准。
- 图里有实心填充（HATCH，ACI 252 的灰色是巷道本体，34 是风机，249 是小设备）和作者上色的线（ACI 1–6，如红色线）。提取时保留，前端按深浅主题换成对应的配色（`client/src/palette.ts`）；这些颜色的含义没有核实，只当作者的视觉意图保留。
- 图上的风量标注是出图时的静态值，只作为底图文字显示，不能当实时数据。

转换链路：`scripts/map/convert_dwg.sh`（Docker 里编译 LibreDWG 0.13.3，DWG → DXF）→ `scripts/map/extract_geometry.py`（容错解析 DXF，剔除图框、图例、标题栏，输出 `var/map/geometry.json`，193 KB：2518 条折线、316 个标注、44 个名称）。转出的 DXF 压缩备份在 `var/ventnet.dxf.xz`（git 忽略）。LibreDWG 的 DXF 里文字带未转义换行，ezdxf 读不了，所以 `scripts/map/dxfscan.py` 自带容错扫描器。

## 3. 架构

```
                 ┌──────────── 浏览器 ────────────┐
   DSH 网页端    │ 上层：DSH 三栏（半透明悬浮面板） │
   （不 fork）   │ 下层：WebGL 画布（three.js）    │
                 └──┬───────────────▲─────────────┘
          cookie 鉴权 │ geometry.json │ SSE：快照 + 指令
                 ┌──┴───────────────┴─────────────┐
   DSH 进程      │ rescue-map 插件（包根入口）      │
                 │   MapHub：校验指令、保存状态、广播 │
                 │   ← map_view 工具、固定流程、监听器告警 │
                 └────────────────────────────────┘
```

- **浏览器端**是 bundle 的客户端包（`dsh.client`，`dsh-bundle/client/src`）：`scene.ts`（地图渲染与控制）、`hud.ts`（悬浮层样式与工具条）、`channel.ts`（SSE 与几何加载）。React 不用，地图和工具条是原生 DOM，面板仍是 DSH 自己的 React。
- **Node 端**是 `src/map`（bundle 根入口，验证清单 #25）：`hub.ts` 是纯逻辑（可测试），`index.ts` 注册三个路由，都校验浏览器 cookie（#27）。
- **悬浮层只改样式不改结构**（#26）：沿用 DSH 的会话区、确认弹窗、交付卡片，人工确认这条安全链路原样保留。选择器依赖 DSH 的哈希类名，版本锁定，升级要重新核对。
- **失败退回**：几何加载或 WebGL 失败时移除样式，DSH 原界面完整可用。救援系统不能因为地图而不可用。

## 4. 地图指令与智能体控制

指令（`MapHub`，Node 与浏览器共用同一组定义）：`focus`（名称，缩放倍数）、`mark`（编号、名称、等级 info/warn/alarm/ok、短文字）、`unmark`、`clear`、`view`（倾斜角 0–60°）。**名称只能是几何数据 `names` 索引里的**，未知名称不执行（fail closed）。标记最多 60 个，文字最长 60 字。

智能体怎么用（P4，已实现 2026-11-09，`src/map/tools.ts`、`tools-plugin.ts`）：

1. **`map_view` 工具**（A 级，只显示，不经 guard，不弹人工确认；放在预设的插件组里，只有 `rescue-commander` 有）。动作：`list`（查地图上的名称，可加 query）、`focus`（定位，缺省放大 4 倍）、`mark`（标记）、`unmark`、`clear`（只清智能体自己的标记）、`view`（倾斜 0–60°）、`reset`（视图复位）。
2. **名称只能是地图上有的**：找不到就拒绝并返回相近的名称，不猜。
3. **标记的内容不由模型写数字**：`mark` 带 `record_id` 时，标签文字和颜色由代码从记录里取（预警等级记录取等级名并按等级着色；阶段记录取阶段名；报警记录取“报警 N 项”；不认识的记录退化成“依据：记录编号”），智能体的备注 note **只能从封闭词表里选**（问题所在、重点关注、需要核查、受影响区域、正在查看；只说“看这里”，不对位置作任何断言、不带数值）；没有记录依据的标记只能是提示色，且必须有 note。最初的版本是“不含数字的短备注”，评测里智能体写出了“主要避灾撤人通道”——没有任何路径数据支撑的断言，不含数字却可能误导操作员，所以改成封闭词表（撤人路线、处置建议只能在回答里说明，并来自工具结果）。记录不存在或编号格式不对（防路径穿越）也拒绝。
4. **边界**：智能体的标记编号是 `agent:<名称>`（同一个位置再标是更新），最多 12 个；系统自动标的 `auto:`（等级、报警、火区）智能体动不了、取消不了；预警等级、矿井报警、火区由系统自动标，人设里写明不要重复标。
5. **指令中心跨插件共享**：`getHub()` 挂在 `globalThis` 上（DSH 重复实例化模块时地图插件和工具拿到的仍是同一个）。
6. **评测**（`eval/agent/cases.yaml` 的 v4-*，判定项 `map_focused`、`map_marks_grounded`、`map_marks_max`、`map_view_errors_max`）：要在 211016 的地图环境里跑（`RESCUE_SIM_PANEL=211016 RESCUE_WATCH_PANELS=211016`，`var/map` 有地图包，之后 `make dev-eval`）。

仍由代码自动做、不占智能体回合的部分：预警等级、矿井报警（告警测点）、火区的标记，以及监听器告警时镜头自动飞到出事位置（P2 已实现）。**受威胁人员、撤人路线的标注还没做**，而且必须由代码从路径数据生成、不能让智能体标：评测里智能体曾自己写出“主要避灾撤人通道”，没有任何路径数据支撑（#34）。

**操作员点选引用**（P3 已实现，`client/src/reference.ts`、`scene.ts` 的 `hitName`）：点地图上的名称（点击与拖动按移动 <5px 区分），往 DSH 输入框里插 `【地图：名称】`，再接着问。输入框是 Lexical 编辑器，用 `execCommand('insertText')`（与打字等价，内部状态同步）而不改 DOM；已有文字补空格；聊天区被隐藏就先显示；输入框不可用（被确认或提问卡片接管）就复制到剪贴板并提示。人设里写明这段文字的含义，评测用例 v4-map-reference。

## 5. 主线：211016 采面

图里有 `211016采面`、`211016回风巷`、`211016运输巷`（图的右下角，一个独立的四边形工作面，经 216 石门接入主系统）。主线演示改用它：

- 现有模拟矿井的场景（s1–s6）用的是 1201 等名称，与图对不上。需要新增场景（暂名 `s7-211016`，参数全是占位值），工作面、回风巷、运输巷的名称与图一致。
- 新增映射表 `scripts/map/mine_map.yaml`（待建）：图上名称 ↔ 模拟矿井的工作面、测点角色（`SensorRole` 词表）。测点在图上的位置 = 名称锚点 + 偏移（例如“上隅角”取采面标注附近的一端），偏移由人对着图量。
- rescue-mine 的真实适配器要提供同样的名称映射，否则地图只显示底图、不叠加实时标记（`get_capabilities` 里可以声明是否支持）。

## 6. 界面布局（大屏）

```
┌──────────────────────────────────────────────────────────────┐
│ LOGO 标题（矿井/图名）     矿井时间 / 本机时间      状态  工具 │  顶栏（自绘）
├─────────┬──────────────────────────────────┬─────────────────┤
│ 左栏    │                                  │ 右栏            │
│ 矿井信息│        通风立体图（底层）          │ 智能体信息      │  自绘
│         ├──────────────────────────────────┤                 │
│         │ 聊天区：DSH 会话组件 + 大屏皮肤   │                 │  DSH 组件换皮
└─────────┴──────────────────────────────────┴─────────────────┘
```

- **自绘**（`client/src/panels.ts`、`hud.ts`）：顶栏、左栏、右栏。数据来自 Node 侧 `/rescue-map/state`（`src/map/state.ts`，纯函数、有测试），浏览器每 3 秒轮询；取不到时显示“状态接口中断”并保留旧数据，不用旧值冒充新值。
  - 顶栏：LOGO、标题（取自图名）、矿井时间（`get_clock`）与本机时间、矿井数据/监听器状态、面板开关、图例、倾斜、复位。
  - 左栏：**预警态势**（等级、阶段、工作面、事件状态、报警数、检测时刻、未确认告警数）、**关键测点**（按传感器分组的最新读数，缺测如实显示）、**事件时间线**、**跟踪计划**。等级和阶段取自监听器写进告警/恢复条目的检测摘要（`data.check`），不在前端或汇总里重算。
  - 右栏：**智能体状态**（来自 DSH 的实时事件：待命/工作中·正在做什么/等待人工确认/等待操作员回答，另有“有告警待处理”“监听降级”；没收到过事件时退回由事件库推断并如实标明；`src/map/activity.ts`）、**待确认指令**（名称、确认人、批准超时取自动作分级表 `action-policy.json`，显示已等待时间和是否已超时升级）、**最近记录**（记录目录里最新的几条）。
- **聊天区复用 DSH 会话组件**（决定于 2026-11-09）：消息渲染、输入框、人工确认、提问卡片、交付卡片仍是 DSH 的，安全链路不动；只去掉它的侧栏和标题，换位置、换皮肤。皮肤做法：强制 body 带 `data-ds-dark-theme`（用 DSH 自己的深色变量），再在这几个容器里把底色变量（`--dsw-alias-bg-*`）换成海军蓝。DSH 的会话列表改成“会话”按钮呼出的抽屉，右栏（文件预览、终端）打开时浮在最上面。
- **完全自绘聊天不做**：要重做人工确认、提问卡片、流式输出等，且人工确认这条安全链路要重新验证；除非有强需求，否则不做。
- 地图的初始视图按“没被面板盖住的区域”适配，面板显示/隐藏时自动重新适配；用户拖动、缩放、定位之后不再自动适配。

## 6.5 地图自动叠加（P2）

不经模型，由 Node 侧每 3 秒把矿井状态画到图上（`src/map/autopilot.ts`，纯逻辑、有测试；定时器在 `src/map/index.ts`，不依赖有没有网页端连着，新连接先收到快照）：

- **预警等级**：事件所在工作面的锚点按等级着色（蓝/黄/橙/红，等级 none 画绿色并写“无预警”），标签是“等级 · 阶段”，来自监听器写进告警的检测摘要。
- **矿井报警**：矿井自己报警平台里仍在越限的测点（`get_alarms`，不是重算的结果），标在测点所在位置，标签写“CO 越限 24.3ppm”——报警记录里的值是越限那一刻的读数，不是当前读数，所以写“越限”。
- **火区**：火区台账（`get_fire_areas`）里的火区标“火区已封闭/已启封”。
- **新告警自动定位**：最近一条告警的编号变了，镜头飞到该事件所在的工作面（第一次只记下已有告警，不飞）。
- 一个位置最多一个标记，多个来源合并成一条标签；位置上有事件时颜色跟随预警等级（报警写在文字里），否则取最严重的。标记编号都以 `auto:` 开头，智能体手动标的不受影响；事件关闭、报警解除后自动清掉。
- **映射表**（`var/map/mine_map.yaml`，跟着地图包走、不进仓库，示例见 `scripts/map/mine_map.example.yaml`）：工作面、巷道、测点 → 地图上的名称。位置的优先级：测点覆盖 > 所在巷道 > 工作面锚点（采空区测点用 goaf_anchor）。**名称不在地图上的条目丢弃并在 DSH 日志里警告**（宁可不显示，也不画到错的地方）；没有映射的测点、工作面不画。
- 左栏的关键测点和矿井报警可以点击：地图飞到对应位置（`client/src/panels.ts`）。
- **演示矿井的工作面名变体**：模拟矿井写死了 1201，改名会牵动大量测试和评测，所以加了环境变量 `RESCUE_SIM_PANEL`（缺省 1201，行为完全不变）；设成 `211016` 时编号、名称、场景文件里的测点引用都换成 211016（`mine.py` 的 `PANEL`），1202 掘进工作面不变；监听器要同时设 `RESCUE_WATCH_PANELS=211016`。Docker 演示：`DEMO_PANEL=211016 make demo-up`（`.env.example` 有说明）。拓扑、测点布置、参数都没变，只是换了名字；真实矿井的适配器要自己回答名称，映射表照样用。

## 8. 风险和待决事项

1. **DOM 选择器脆弱**：面板样式依赖 DSH 的哈希类名。缓解：版本锁定、选择器集中在 `hud.ts`、评测加“选择器匹配数”检查；升级 DSH 前必须重核。
2. **底图只有线**：巷道是细线，没有填充，“3D 感”有限。P1 要做填充；如果有真实标高数据，再考虑真三维。
3. **WebGL 可用性**：开发环境用软件渲染也能跑（SwiftShader）；真实矿井终端的显卡情况未知，要给出降级（二维 Canvas/SVG）还是只保证退回原界面，待定。
4. **名称映射**：真实矿井适配器如何提供名称映射，要写进 rescue-mine 接口（`interface.py`）；本版只在模拟矿井实现。
5. **状态在内存里**：Node 进程重启标记丢失（P5 落盘）。落盘的话要不要按事件隔离、事件关闭后清理，待定。
6. **右栏、窄屏已验证（P1）**；输入法、操作员聊天输入框的快捷键仍未验证。
7. **安全边界**：地图只读展示，不引入新的写矿井途径。`/rescue-map/emit` 调试路由只在 `RESCUE_MAP_DEBUG=1` 时存在，演示和生产环境不开。
8. **图的保密**：真实矿井图不进仓库（决定于 2026-11-09，见下一节“地图包”）。

## 9. 地图包：两次演示用两张图

有两次演示：**内部演示**用现在这张图（某矿采一区），**现场演示**的矿井图等客户提供。所以底图不是代码的一部分，而是可替换的“地图包”：

- 位置：`var/map/`（git 忽略；里面有 `geometry.json` 和提取配置 `extract.json`；`var/demo/` 之外，`make demo-reset` 不清它）。当前矿井的底图固定叫 `geometry.json`，换矿井图只换这个文件。
- 读取：DSH 进程读 `RESCUE_MAP_DIR`（缺省 `$RESCUE_HOME/var/map`）。Docker 里 `../var/map` 只读挂载到 `/data/map`，`scripts/demo.sh` 启动前先建目录，避免 Docker 建出 root 所有的空目录。
- 没有这个文件（或客户端加载失败）时，浏览器端退回 DSH 原界面，系统照常工作；这也是在别的机器上克隆仓库后的默认状态。
- 生成：`scripts/map/convert_dwg.sh` + `scripts/map/extract_geometry.py`。图框、图例、标题栏的范围和视图在模型空间里的位置，写在地图包的 `extract.json` 里（格式见 `scripts/map/extract.example.json`，P1 已从代码里移出），**拿到客户的图要重新量、重写**；名称分类规则（`extract_geometry.py` 的 `NAME_WORDS`）也可能要调。
- 仓库里只有代码和对内部演示图的“形状”假设；主线工作面名称（211016）、映射表 `mine_map.yaml` 也是按图分的，换图要换一份。测试 `test_iso_geometry_invariants` 在没有地图包时跳过。
