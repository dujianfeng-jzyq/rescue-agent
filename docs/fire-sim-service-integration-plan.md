# 火灾推演服务接口测试情况与配合事项（MineFireSimulation）

日期：2026-11-17　测试地址：内网 192.168.0.200:5079

我们对贵方的火灾推演服务 `MineFireSimulation` 做了接口测试。我们的应用场景是采空区煤自燃，推演结果将作为有害气体蔓延范围和到达时间的参考。下面列出测试情况、发现的问题和需要贵方配合的事项，请优先答复第二节的第 1–9 条。

## 二、需要贵方配合的事项

### 必须说明或修正（影响结果能否使用）

1. **火灾对风流的影响**：大火（5000 kg、300 m²）时各巷道风速变化不超过 0.012 m/s，没有风流反转。火风压和节流效应是否已计入通风网络解算？是否要给出 z 坐标（高差）才会体现？风流紊乱（反转、停风）是火灾时撤人最关心的结果之一。
2. **燃料质量的作用**：10–500 kg 的结果完全相同，5000 kg 时 CO 反而大幅下降。燃料质量和燃烧面积在模型里分别起什么作用？5000 kg 的结果是否正常？
3. **采空区火源和阴燃阶段**：能否模拟采空区内的火源（漏风通道上的阴燃、低氧燃烧）？煤自燃早期多为阴燃，用明火模型推演是否合适？如果合适，燃烧面积、燃料质量、氧气浓度该怎样取；如果不合适，有没有建议的做法？
4. **部分巷道作火源时报 500**（示例网络的 0、6、9、10、12、23、33、37、39 号）：原因是什么？能否修正；如果这些巷道确实不能作火源，请改为返回 400 并说明原因。复现数据另附（`火源巷道500复现数据.zip`：9 个完整请求体和复现命令）。
5. **CO 浓度的精度**：结果保留 3 位小数（vol%），即分辨率 10 ppm，而《煤矿安全规程》CO 最高允许浓度是 24 ppm。能否多保留几位，或直接给 ppm？
6. **结果的适用范围和模型依据**：推演结果能否直接作为指挥人员参考的蔓延范围？模型是否经过验证或用于过实际矿井？哪些情况下结果不可信？燃烧模型（热释放速率曲线、CO 生成率）和烟流模型的依据；`fuelType` 各种燃料的参数。
7. **可用性**：是否 7×24 运行，重启后能否自动恢复，有没有计划停机、停机前怎样通知，出现故障时联系谁。
8. **响应时间**：典型和最长响应时间，与节点数、巷道数、推演时长的关系；规模上限。
9. **错误的含义**：哪些是输入问题（400）、哪些是服务内部问题（5xx，可以重试）；错误返回的格式能否统一（目前请求体不是合法 JSON 时格式不同）。

### 希望支持

10. **健康检查接口**（如 `GET /healthz`），以便提前知道服务不可用。
11. **结果里带计算方法版本号**（如 `version`），复盘时能知道当时用的是哪一版。
12. **巷道可选填实际长度和高差**（如 `branches[].length`、`branches[].rise`），填了就优先于按坐标计算的结果。通风网络图通常是示意图，没有可靠坐标时也能使用服务。
13. **其他输出**：除 CO 外，能否输出烟雾（能见度）、温度、O₂ 浓度。
14. **未知字段返回 400**，不要静默忽略，避免字段名写错却得到看似正常的结果。
15. **鉴权**：至少支持一个固定令牌（`Authorization: Bearer <令牌>`），或按 IP 白名单限制访问。
16. **输出规模**：能否只返回每条巷道每帧的最大值，或可以指定网格间距。真实矿井网络的结果可能有几十 MB。

### 请说明

17. `fixedFlow`（强制分风量）、`closed`（风门）和抽出式（`mode = 2`）怎么用；能否用来推演关闭风门、反风、调风的效果。
18. 服务日志放在哪里，接口变更怎样通知。
