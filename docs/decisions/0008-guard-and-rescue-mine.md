# 0008 第三版：rescue-mine 接口与 guard 守卫，动作分级

状态：采纳（2026-11-05）。细化 0002（指令统一走 actions、三道防线）和 0005（模拟矿井与真实矿井共用同一契约）；设计见 `docs/design-v3.md`。

## 背景

第二版的 `mcp/actions` 同时做两件事：校验指令（红线、记录核对），和把确认后的处置经模拟器的控制接口（`/sim/interventions`）转发出去。
后者是模拟器专有的通道，真实矿井没有；换矿时 actions 要跟着改，安全逻辑就得重审。另外，第一版的研判快照（`snapshot_id`）在
契约、校验、actions、测试里还留着一整条并行路径，防灭火方案和启封方案只能按快照核对，而快照的生成者（第一版 workflow）早已删除。

## 决定

1. **rescue-mine 是矿井的唯一接口，只有“读数据”和“执行动作”，不含策略。** 通知、调度、处置用三个写入类工具
   （`send_notice`、`dispatch_order`、`submit_treatment`）执行，返回回执，异步生效的用 `get_action_status` 查询；相同幂等键只执行一次。
   接口表在 `rescue_contract/interface.py`，说明文档由代码生成（`docs/rescue-mine-interface.md`）。
2. **guard（`mcp/actions` 演变而来）是智能体所有对外动作的唯一通道，也是唯一的安全逻辑所在。** 红线、记录核对、动作分级、台账都在这一侧；
   校验通过后才调用 rescue-mine 的写入类工具。guard 不再持有模拟器的控制令牌，不再调用 `/sim/`。
3. **写入类工具另认写入令牌**（`RESCUE_MCP_MINE_ACT_TOKEN`，只有 guard 持有）。读令牌（证据插件用）调用写入工具被拒；
   中间件按 JSON-RPC 的工具名区分，批量请求夹带也拒。证据插件能读矿井、不能下发。
4. **动作分级 A/B/C 集中在一张表**（`rescue_contract/action_policy.py`），导出为 `dsh-bundle/data/action-policy.json` 给审批插件：
   C 级（对外动作）弹确认，A、B 级不弹；**没有登记的工具按 C 级处理**。审批插件不再按工具名前缀放行（`precheck_`、`query_`），
   确认人也不再在插件配置里重复写一遍。批准超时、超时升级对象写在表里，由 P3 的监听器执行。
5. **指令一律引用记录（`record_id`）。** 删除第一版的 `Snapshot`、`snapshot_id`、`HumanInput`；`WarningNotice`、`Escalation` 的 `record_id` 必填。
6. **删除 `issue_firefighting_plan` 和 `approve_unsealing`。** 它们只能按第一版草案快照核对，没有第二版的生成流程，
   留着就是没有核对依据的对外动作（违反“指令必须引用记录”）。启封审批在演示故事线里（design-v3 第 9 节第 7 步），随新流程按记录重做。
7. **撤人名单、调度单在预检阶段（人工确认之前）按矿井数据核对**：名单里的人在井下、调度节点和物资在台账里、不超库存；取不到矿井数据按不通过处理。
8. **矿井执行失败不假装成功。** 方案按步骤逐条提交，中途失败就停，台账记 `failed` 和已执行的回执，告诉智能体“已执行到第几步”；
   失败的不算“已下发”（复评取处置开始时间的查询看不到它）。矿井拒绝执行的步骤（如需人工执行的监测）在回执里如实列出，不算失败。
9. **服务名、端口、工具名不变**（`mine_data` 8101、`actions` 8106）。改名牵动预设、令牌、Docker、审批插件的前缀，收益只是名字，留到真有必要时再做。

## 后果

- 换矿只改 rescue-mine 的实现；安全逻辑不动、不用重审。对接方有一份一致性检查（`python -m rescue_contract.conformance`）可以自测，写入类检查默认关闭，避免对真实矿井误下发。
- 三道防线有了跨语言的集成测试（`mcp/actions/tests/test_three_lines.py`）：审批插件的真实 TS 代码对真实 guard 预检，再绕过审批直接调 guard。第二道（人工确认）在 DSH 里，只能由端到端评测覆盖。
- 防灭火方案下发、启封审批暂时没有工具；演示故事线的第 7 步要在后续阶段补上（按记录、走 C 级）。
- 批准人按角色限定仍未做：需要 DSH 的用户身份，目前确认人只用于弹窗显示。
- 真实矿井异步生效时，台账里的回执只是“已接收”；后续状态要查 rescue-mine。复盘时间线（P5）要把它们对上。
