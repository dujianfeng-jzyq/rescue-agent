# 真实矿井演示集成清单

把智能体接到一座真实矿井上做演示（以及之后的只读接入、试运行）要准备的事项。2026-11-12 建立。
依据：`docs/implementation-plan.md`“接入真实矿井的三个步骤”和“大模型接入”、`docs/rescue-mine-interface.md`（接口）、`docs/architecture.md`、`docs/progress-log.md`“代码复查”的遗留项。参数类事项见 `docs/expert-review.md`（“时机”列为“接入前”的条目）。

**原则**：rescue-mine 是唯一随矿井变化的部分。接一座矿 = 写一个实现 rescue-mine 接口的适配器、准备地图包和本矿参数；智能体、技能、插件、guard 不改。演示和只读接入阶段**不向井下系统写任何东西**，智能体只出建议，对外动作由人按现行制度执行。

“负责”列：**客户** = 矿方提供或配合；**我们** = 开发；**专家** = 通风、防灭火、救护专家；**IT** = 矿方或集团信息部门（网络、模型、知识库）。

## 0. 先定下来的事

| # | 事项 | 选项 / 建议 | 负责 |
| --- | --- | --- | --- |
| 0.1 | **演示形式** | A 实时只读：接真实数据实时运行，展示常驻监听、研判和报告；平时没有火情，看不到预警和封闭的全流程。B **历史数据回放**（建议与 A 搭配）：用该矿一次真实的自燃预警过程的历史数据，按矿井时钟回放给智能体，能走完整流程；要新做“回放适配器”（实现 rescue-mine 读接口，时钟可加速）。C 真实矿图 + 模拟数据：就是现在的 Docker 演示（工作面 211016 已对上真实矿图），不需要矿方数据，但读数是模拟的。 | 客户、我们 |
| 0.2 | 接入阶段 | 按实施方案三步走：离线数据验证（只要数据）→ 只读旁路接入（只读地面数据平台）→ 试运行（与人工指挥并行）。演示通常在第 1 或第 2 步 | 客户、我们 |
| 0.3 | 只读阶段对外动作怎么落地 | 建议：适配器实现写入类工具，但一律返回 `rejected`（“只读接入，需人工执行”），guard 照常校验、弹确认、写台账，回执里的“矿井没有执行”提示人工执行；或者 `get_capabilities` 不声明 `notice`/`dispatch`/`treatment` 功能（需先确认 guard 对缺功能的处理，见第 7 节） | 我们 |
| 0.4 | 演示的工作面 | 选一个有束管监测、上隅角和回风巷安全监控、最好有采空区测温的综采工作面；名称同时配置给模拟矿井（`RESCUE_SIM_PANEL`）和监听器（`RESCUE_WATCH_PANELS`） | 客户 |
| 0.5 | 数据使用许可 | 客户数据原则上不出内网；本地模型就绪前要用外部 API 处理客户数据，须客户书面同意并脱敏 | 客户 |

## 2. 数据接口：rescue-mine 适配器

接口说明见 `docs/rescue-mine-interface.md`（接口 1.0.0，契约 0.12.0）。

**必需工具与本矿数据源**

| 工具 | 内容 | 本矿数据源（待填） | 备注 |
| --- | --- | --- | --- |
| `get_capabilities` | 接口版本、实际提供的工具和功能 | — | 如实声明，不提供的功能不声明 |
| `describe_mine` | 工作面拓扑（进回风巷、采空区、避难硐室） | 矿图、通风系统 | |
| `get_clock` | 矿井时钟 | 系统时间（实时）/ 回放时钟 | 一律矿井本地时间，不带时区 |
| `list_sensors` | 测点：来源、参数、巷道、工作面、**语义角色** | 安全监控、束管、测温系统的测点表 | 每个测点标 `panel` 和 `role`，见下 |
| `get_latest`、`get_readings` | 最新和历史读数，带数据质量标记 | 数据汇聚平台 | 故障、标校、断线要标 `missing`/`suspect` |
| `get_events` | 监控系统自身的超限、故障事件 | 安全监控系统 | |
| `get_fire_areas` | 火区台账：封闭、启封时间 | 通风部门台账（多为表格） | 可能要做导入工具 |
| `get_network` | 通风网络：节点、巷道、长度、断面、风量 | 通风系统图、通风网络解算软件 | 没有断面时用缺省 12 m²（专家清单 11） |
| `get_personnel` | 井下人员实时位置 | 人员定位系统 | 用 `PersonnelSnapshot.of(名单)` 构造 |
| `get_inventory`、`get_rescue_teams` | 应急物资、救援力量台账 | 多为表格 | 可能要做导入工具 |

**可选功能**：`alarms`（矿井报警平台，`get_alarms`）、`equipment`（风机、水泵、制氮、注浆设备状态）、`notice`/`dispatch`/`treatment`（写入类，演示和只读阶段见 0.3）。提供任一写入功能时必须实现 `get_action_status`。

**清单**

- [ ] 测点到语义角色的映射：上隅角 `upper_corner`、回风巷 `return_airway`、进风巷 `intake_airway`、采空区束管 `goaf_gas_tube`、采空区测温 `goaf_temperature`、总回风 `main_return`，其余 `other`；词表不够用的提给我们和专家（专家清单 41） · 我们、客户
- [ ] 测点的参数代码（CO、CH₄、O₂、C₂H₄、C₂H₂、CO₂、TEMP 等）和单位统一到契约 · 我们
- [ ] 数据质量标记的规则（断线、标校、超量程怎么映射为 `missing`/`suspect`） · 我们、客户
- [ ] 输入错误抛 `ToolError` 并写明原因（其他异常的说明传不到智能体） · 我们
- [ ] 读写令牌分离：读工具认 `RESCUE_MCP_MINE_DATA_TOKEN`，写入工具另认 `RESCUE_MCP_MINE_ACT_TOKEN`（只有 guard 持有） · 我们
- [ ] 一致性检查通过：`python -m rescue_contract.conformance <适配器 URL>`（**不加** `--with-actions`，它会真的执行动作，只对测试环境用） · 我们
- [ ] 回放适配器（选 0.1 的 B 时）：读历史数据、时钟可设起点和倍速；回放控制不经 rescue-mine，智能体看不到 · 我们

## 5. 部署环境

| # | 事项 | 说明 | 负责 |
| --- | --- | --- | --- |
| 5.1 | 网络 | 矿区内网私有化部署，数据不出网；演示环境要能完全离线运行（模型用本地部署的） | IT |
| 5.2 | 服务器 | Docker（现在的演示环境 4 个容器：模拟矿井/适配器、guard、监听器、DSH 网页端）；考虑信创硬件、等保要求、指挥中心关键节点冗余 | IT、我们 |
| 5.3 | 大模型 | 本地部署，OpenAI 兼容接口，`profiles/local-llm.patch.yml`（`RESCUE_LLM_BASE_URL`、`RESCUE_LLM_API_KEY`、`RESCUE_LLM_MODEL`）；要求：稳定支持工具调用、上下文 ≥ 64K、能支撑主智能体与固定流程阶段并发 | IT |
| 5.4 | 模型准入测试 | 换模型前跑同一套测试：工具调用正确率、结构化输出合规率、6 个标准场景端到端（`make eval-agent`）、红线违规建议比例；不低于开发期 DeepSeek 基线才切换。注意：provider 重试要加 `STREAM_CLOSED`；DSH 结构化输出的 schema 限制（CLAUDE.md “已知坑”） | 我们 |
| 5.5 | 知识库 | RAGFlow 由 IT 部署；本矿预案、灾害预防和处理计划入库（`KB_DATASETS_PLANS`），规程入库后生成条文索引并请专家抽查（专家清单 40）；RAGFlow 不可用时降级为本地条文检索 | IT、我们、专家 |
| 5.6 | DSH | 锁定 0.2.1-rc.4；`DSH_*` 变量必须 export；镜像要装中文字体（否则 Word 预览不可用）；DSH 不持有矿井写入令牌和 `/sim` 控制令牌 | 我们 |
| 5.7 | 令牌 | 按服务拆分且都要设置：`RESCUE_MCP_MINE_DATA_TOKEN`（证据插件只读）、`RESCUE_MCP_ACTIONS_TOKEN`（主预设和审批预检）、`RESCUE_MCP_MINE_ACT_TOKEN`（只有 guard）。**现在本机运行时没配令牌服务不鉴权**，真实部署必须配齐（见第 7 节） | 我们 |
| 5.8 | 跨容器访问 | 按服务名访问要把主机名加进 `RESCUE_MCP_ALLOWED_HOSTS`（否则 421）；证据插件的脚本运行目录单独给 `RESCUE_RUN_DIR` | 我们 |
| 5.9 | 数据卷 | 记录 `var/records/`（只有 DSH 进程可写，guard 只读挂载）、事件库、指令台账、审计日志；台账和审计是复盘依据，不得修改，要定备份和保存期限 | 我们、IT |
| 5.10 | 关掉模拟专属的部分 | 真实矿井没有 `/sim` 控制接口（`RESCUE_SIM_CONTROL_URL` 留空）、演示控制台和演示导演；值班状态文件 `duty-status.json` 原来给导演用 | 我们 |
| 5.11 | 账号 | DSH 网页端登录账号；确认弹窗现在不区分登录人的角色（见第 7 节） | IT、我们 |

## 7. 对接真实矿井前要做的代码改动（代码复查遗留）

来自 `docs/progress-log.md`“代码复查”小结。演示用回放适配器、只读接入时，标 ★ 的会直接碰到。

| # | 事项 | 现状 | 影响 |
| --- | --- | --- | --- |
| 7.1 | ★ 技能脚本按测点角色和 `panel` 字段取数 | 7 处按模拟矿井的测点编号找测点（`SM-{panel}-UC/RET`、`BT-` 前缀）并按“编号含工作面号”筛测点和巷道 | 真实矿井的测点编号不同：上隅角、回风巷 CO 不参与分级，甲烷报警可能把束管算进去。**必须先改** |
| 7.2 | ★ 报警平台取数失败与“没有报警平台”区分 | `get_alarms` 任何异常都记为没有平台 | 平台临时不通时矿井的未恢复报警会悄悄从研判里消失 |
| 7.3 | ★ 没配令牌时拒绝启动 | 没配令牌不鉴权；没配写入令牌时只读令牌能调写入工具 | Docker 演示强制必填，本机和真实部署要防漏配 |
| 7.4 | 方案按步骤下发时前一步被拒或未完成要停 | 只有启封是按顺序（`ordered`），且不等异步执行完成 | 只读阶段写入全部拒绝时影响不大；试运行接写入前必须改 |
| 7.5 | 只读阶段 guard 的处理 | 没验证过适配器不声明写入功能、或写入一律 `rejected` 时 guard、弹窗、台账的表现 | 定 0.3 后补测试 |
| 7.6 | 记录整条加哈希或签名 | `content_sha256` 只覆盖内容，来源、时效、工作面不在哈希里，防篡改靠目录权限 | 试运行前 |
| 7.7 | 数据质量参数挪进 `references/` | 尖峰倍数、卡值点数、校核容差写在 `_quality.py` | 便于按本矿调（专家清单 9） |
| 7.8 | 人工标记测点故障 | 未做；人工改等级只能往高调 | 真实测点出故障时没有可复核的降级途径（专家清单 34） |
| 7.9 | 批准人按角色限定 | 确认弹窗谁登录都能点 | 需要 DSH 用户身份；试运行前要有 |
| 7.10 | 本矿参数覆盖机制 | 见第 4 节 | 多矿部署前 |
| 7.11 | 回放适配器 | 未做 | 选 0.1 的 B 时 |
| 7.12 | 只有单元测试、没在 Docker 演示实跑的改动 | 第 2–4 轮复查的改动和 2026-11-12 的回差、提前判恶化、封闭后不弹橙色卡片 | 演示前跑一次 `eval/agent/demo_run.py` |

## 8. 安全与合规

- [ ] 演示和只读阶段不向井下系统写入；写入令牌不发给适配器以外的任何服务 · 我们
- [ ] 撤人和报告由调度员按预案立即执行，不等待智能体（演示时明确讲） · 演示人员
- [ ] 智能体只出建议；对外动作都经红线校验和人工确认；台账、审计日志留存 · 我们
- [ ] 客户数据不出内网；需要带出时书面同意并脱敏 · 客户、我们
- [ ] 对外介绍注明指标来自模拟或回放环境，真实效果在试运行中确认 · 演示人员
